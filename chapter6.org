* Chapter 6: Building Our Own "Arc"

- *std::sync::Arc<T>* allows for shared ownership through reference
  counting.
- The shared allocation will be dropped once the Arc and all it's
  clones are dropped.

* Basic Reference Counting

#+begin_src rust :results value verbatim :exports both
  use std::ops::Deref;
  use std::ptr::NonNull;
  use std::sync::atomic::{fence, AtomicUsize, Ordering};

  struct ArcData<T> {
      ref_count: AtomicUsize,
      data: T,
  }

  pub struct Arc<T> {
      ptr: NonNull<ArcData<T>>,
  }

  unsafe impl<T: Send + Sync> Send for Arc<T> {}
  unsafe impl<T: Send + Sync> Sync for Arc<T> {}

  impl<T> Arc<T> {
      pub fn new(data: T) -> Arc<T> {
	  Arc {
	      ptr: NonNull::from(Box::leak(Box::new(ArcData {
		  ref_count: AtomicUsize::new(1),
		  data,
	      }))),
	  }
      }

      fn data(&self) -> &ArcData<T> {
	  unsafe { self.ptr.as_ref() }
      }
  }

  impl<T> Deref for Arc<T> {
      type Target = T;

      fn deref(&self) -> &T {
	  &self.data().data
      }
  }

  impl<T> Clone for Arc<T> {
      fn clone(&self) -> Self {
	  // TODO: Handle overflows.
	  self.data().ref_count.fetch_add(1, Ordering::Relaxed);
	  Arc { ptr: self.ptr }
      }
  }

  impl<T> Drop for Arc<T> {
      fn drop(&mut self) {
	  // TODO: Memory ordering.
	  if self.data().ref_count.fetch_sub(1, Ordering::Release) == 1 {
	      fence(Ordering::Acquire);
	      unsafe {
		  drop(Box::from_raw(self.ptr.as_ptr()));
	      }
	  }
      }
  }

  fn main() {
      let p1 = Arc::new(1);
  }
#+end_src

#+RESULTS:

Memory ordering comment:

- In Drop implementation, we cannot use Relaxed because we want to
  ensure that nothing is still accessing the data when we drop it.
- We want to ensure that the final fetch_sub method must establish
  happens-before relationship with the previous fetch_sub
  operation. We can do that using release and acquire ordering. Eg:
  Decrementing two to one effectively releases the data, while
  decrementing one to zero "acquires" ownership of it.
- We can use *AcqRel* which covers the case, but only the final
  decrement to zero needs the *Acquire* while the others only need
  *Release*. For efficiently, we use *Release* for the ~fetch_sub~
  operation and a separate *Acquire* fence only when necessary.
